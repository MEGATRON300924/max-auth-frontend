## Current task: Coordinate MAX Auth refresh requests across tabs and products (2026-11-17)

### Root cause
- The module-level refresh promise only coalesces requests inside one JavaScript runtime.
- Different browser tabs and MAX product origins can concurrently send the same host-only refresh cookie to `auth.max-ai.name.ng`.
- Backend now responds with `REFRESH_TOKEN_ROTATED` for a just-won rotation race rather than revoking every account session.

### Implementation on `fix/refresh-token-coordination`
- Added Web Locks coordination (`max-auth-refresh`) for tabs on the same browser origin, with a fallback for browsers without Web Locks or when lock acquisition fails.
- Added bounded retries for the backend's `REFRESH_TOKEN_ROTATED` response, allowing the winning request's Set-Cookie response to update the shared cookie before retry.
- Retained the existing in-tab `refreshPromise` single-flight behavior and access-token storage model.
- No auth endpoints, login flow, or rate limits were changed.

### Verification
