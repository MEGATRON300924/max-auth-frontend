## Follow-up: MAX Auth session restoration across first-party pages (2026-11-14)

- Main-site pages now attempt the existing OAuth refresh-token restoration first, then fall back to a credentialed POST to the host-only MAX Auth /api/v1/auth/refresh endpoint.
- After refresh, the page reads /api/v1/auth/me with the returned session access token and restores the profile without exposing the refresh cookie to sibling subdomains.
- The frontend API client already uses credentials: include for MAX Auth API calls, so the Socials/Connected Apps portal retains its existing secure cookie-refresh flow.
- The cross-subdomain behavior still requires a browser test with an active MAX Auth session and the production cookie settings.
